# M0 walkthrough: the scaffold

## What was built
An empty but working monorepo. Two shared packages (`packages/core` for the calculation library, `packages/db` for database access), three apps (`apps/api`, a NestJS HTTP server; `apps/worker`, a NestJS process with no HTTP port; `apps/web`, a Next.js placeholder page), a Docker Compose file that starts PostgreSQL, a CI workflow, and one trivial test per workspace. The API already answers `GET /healthz` (always 200) and `GET /readyz` (200 only if the database answers `select 1`, otherwise 503).

## Design decisions
1. **Config is parsed once, in one file.** `apps/api/src/config.ts` validates environment variables with Zod and exits with code 1 and a list of problems if anything is wrong. Every other file receives the parsed `Config` object by injection, so the rest of the code never touches `process.env`.
2. **The clock is a service.** `ClockService.today()` is the only way code learns today's date. Setting `FIXED_TODAY` freezes it, which is what makes seed data and tests deterministic later.
3. **Packages build before they are used.** The apps import `core` and `db` through their compiled `dist/` folders, so the root `typecheck`, `test` and `test:e2e` scripts build the packages first. This avoids running TypeScript from `node_modules`.
