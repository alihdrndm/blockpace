# M3 walkthrough: the HTTP API

## What was built
`apps/api` now serves every endpoint in the spec. Blocks can be created, listed (newest first, with today's risk summary), read, patched and deleted. Snapshots of pickup are saved one date at a time with `PUT`, or many at once from a CSV upload. Each block can be evaluated live or as of an earlier date, and `pace` returns one point per snapshot for the chart. A stateless calculator answers "what would we owe?" without saving anything. Webhook endpoints can be registered, listed, deleted and sent a test ping, and alerts and deliveries can be listed. Every `/v1` route needs the `x-api-key` header and is rate limited to 120 requests a minute per IP address. Every error is an `application/problem+json` document with a stable `code`.

## Design decisions
1. **Write and re-evaluate in one transaction.** A snapshot write, a snapshot delete, or a change to a block's terms or cutoff calls `recordEvaluation` inside the same database transaction. Either the new data, the new evaluation and any alerts are all saved, or nothing is.
2. **One source of truth for shapes.** Request and response shapes are the Zod schemas in `packages/core`. NestJS validates with them directly and Swagger (`/docs`) is generated from them, so the docs cannot drift from the code.
3. **Fail loudly and safely.** One global filter turns every error into problem+json. Expected failures carry a precise code (for example `SNAPSHOT_NIGHTS_MISMATCH` lists the missing and the extra dates). Unexpected ones become a bare 500 whose details go only to the server log.

## Read first
- `apps/api/src/bootstrap.ts` and `app.module.ts`: how the app is assembled (the tests use the same code).
- `apps/api/src/snapshots/snapshots.service.ts`: the transactional write path and the 400-snapshot limit.
- `apps/api/src/snapshots/snapshot-csv.ts`: the CSV import rules, tested without a database.
- `apps/api/src/errors/problem.filter.ts` together with `docs/ERRORS.md`.
- `apps/api/test/*.e2e.test.ts`: every endpoint against a real PostgreSQL.
