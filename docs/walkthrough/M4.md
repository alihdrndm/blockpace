# M4 walkthrough: the worker

## What was built
`apps/worker` is a second NestJS process with no HTTP port. It does two jobs. Every day at 00:05 UTC, and once when it starts, it re-evaluates every active block, so cutoff reminders and stale-report alerts fire even when nobody opens the app. Every 10 seconds it sends the webhooks the API queued: it signs each request, posts it, and records the result. A failed delivery is retried after 1 minute, 5 minutes, 30 minutes, 2 hours and 12 hours, then marked failed. `tools/webhook-sink.ts` is a tiny receiver for demos that prints whether each signature checks out.

## Design decisions
1. **The database is the queue.** Deliveries are rows in `webhook_deliveries`. The worker picks up to 20 due rows with `FOR UPDATE SKIP LOCKED`: rows another worker has locked are skipped, not waited for. Two workers can therefore run side by side and still never send the same webhook twice, which a test proves with two loops draining 30 deliveries at once.
2. **Signed bytes are sent bytes.** The body is turned into a string once; that exact string is both signed (HMAC-SHA256 over `timestamp.body`) and sent. Signing the timestamp lets receivers refuse old requests that someone replays.
3. **Everything that varies is injected.** The clock, `fetch` and DNS lookup are passed in, so tests walk through the whole retry schedule by moving a fake clock instead of waiting 15 hours, and they talk only to local test servers.

Each block in the daily job gets its own transaction, so one broken block is logged and skipped while the rest are still evaluated.
