# M2 walkthrough: the database layer

## What was built
`packages/db` now owns everything PostgreSQL. `schema.ts` defines the 8 tables, a generated SQL migration in `drizzle/` creates them, and `migrate.ts` applies it. `recordEvaluation` is the one routine that evaluates a block, stores the result and raises alerts. `seed.ts` fills a fresh database with three demo blocks, and the `db:migrate`, `db:seed` and `db:reset` scripts run them.

## Design decisions
1. **The database enforces "exactly once".** An alert has a unique key (block, type, dedupe key). `recordEvaluation` inserts with `on conflict do nothing` and only counts rows that were really inserted, so running it twice, or from two workers at once, cannot raise the same alert twice. No locking code is needed.
2. **It runs in the caller's transaction.** The API will call it right after writing a snapshot, so the snapshot, the evaluation, the alerts and the webhook delivery rows commit together or not at all. A test proves a failure afterwards rolls everything back.
3. **Real database in tests.** Tests start an actual PostgreSQL 17 container, so constraints, cascades and `on conflict` behave exactly as in production. Nothing is mocked.
